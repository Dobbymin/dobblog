# 구름 배경 CSS 재현 레시피

참조 이미지의 구조: 위쪽은 하늘색 그라데이션, 아래로 갈수록 밝아지는 구름 아치가 **3개 레이어**로 겹쳐 쌓이고, 맨 앞 레이어는 흰색이며 화면 하단을 꽉 채운다. 각 아치는 크기가 제각각이고 서로 겹친다.

## 기법 S — 인라인 SVG 비대칭 베지어 (채택, 참조 사이트 기법 실측 재현)

**구름은 CSS gradient보다 SVG가 맞다.** `radial-gradient`는 타원 하나밖에 못 그려서 봉우리가 균일해지고 벽지처럼 보인다. 참조 사이트도 인라인 SVG `path`를 쓴다.

### 반응형 — SVG를 화면보다 넓게 두고 잘라낸다

참조 사이트 실측:
```
1280px 뷰포트 → SVG width 5120px   (viewBox와 1:1, 왜곡 0)
375px  뷰포트 → SVG width 2512.5px
viewBox="0 0 5120 357", height 357px, 부모는 flex + overflow clip
```

역산하면 **`min(5120px, 670vw)`**. 넓은 화면에서는 viewBox 폭과 같은 5120px로 고정해 곡선 왜곡을 0으로 만들고, 좁은 화면에서는 670vw로 줄여 봉우리가 너무 적게 보이는 것을 막는다. 부모가 가운데 정렬한 뒤 넘치는 부분을 자른다.

```jsx
<section style={{ display: 'flex', justifyContent: 'center', overflow: 'hidden',
  height: '357px',
  backgroundImage: 'linear-gradient(to bottom, var(--color-sky-from), var(--color-sky-to))' }}>
  <svg viewBox='0 0 5120 357' preserveAspectRatio='none' aria-hidden='true'
       style={{ width: 'min(5120px, 670vw)', minWidth: 'min(5120px, 670vw)',
                height: '100%', display: 'block', flex: 'none' }}>
    {layers.map(({ color, start, gaps, ys }) => (
      <path key={color} d={buildPath(mk(start, gaps, ys), 357)} fill={color} />
    ))}
  </svg>
</section>
```

### 곡선 — 제어점 비대칭이 구름다움을 만든다

참조 사이트 `path`의 제어점 비율에 규칙이 있다:

| 구간 | 제어점 비율 | 결과 |
|---|---|---|
| y가 커짐 (골로 내려감) | `[0.66, 0.80]` | 골이 뾰족 |
| y가 작아짐 (봉우리로 오름) | `[0.14, 0.32]` | 봉우리가 넓고 평평 |

제어점의 y는 각각 시작점 y와 끝점 y를 쓴다 — 정점에서 접선이 수평이 되어 부드럽게 이어진다.

```js
function buildPath(pts, vbH) {
  let d = `M ${pts[0][0]} ${pts[0][1]}`;
  for (let i = 1; i < pts.length; i++) {
    const [x0, y0] = pts[i - 1], [x1, y1] = pts[i];
    const s = x1 - x0;
    const [r1, r2] = y1 > y0 ? [0.66, 0.80] : [0.14, 0.32];
    d += ` C ${x0 + s*r1} ${y0} ${x0 + s*r2} ${y1} ${x1} ${y1}`;
  }
  return d + ` L ${pts.at(-1)[0]} ${vbH} L ${pts[0][0]} ${vbH} Z`;
}
// start에서 시작해 gaps를 순환하며 x 누적, ys를 순서대로 y로
function mk(start, gaps, ys) {
  const pts = []; let x = start;
  for (let i = 0; i < ys.length; i++) { pts.push([x, ys[i]]); x += gaps[i % gaps.length]; }
  return pts;
}
```

`fill`은 CSS 변수를 참조해야 다크모드가 자동 전환된다. 앞 레이어를 `--color-background`로 두면 구름 하단이 본문 배경과 이어진다.

### 치명적 함정 S1 — 제어점 비대칭은 인덱스가 아니라 방향으로 정한다

`i % 2`로 번갈아 적용하면 정점 배열의 첫 값이 봉우리냐 골이냐에 따라 위상이 뒤집혀 **뾰족한 산맥**이 나온다. 반드시 `y1 > y0` 비교로 정하라. 그래야 배열과 무관하게 "골은 항상 뾰족, 봉우리는 항상 평평"이 유지된다.

### 치명적 함정 S2 — y 편차를 키우면 모바일에서 무너진다

좁은 화면에서는 `670vw`가 viewBox 폭보다 작아 가로가 압축된다(375px에서 0.49배). 세로는 그대로이므로 **y 편차가 클수록 봉우리가 세로로 길쭉해져 첨탑이 된다.**

y 편차를 약 95 이내로 유지하라. 참조 사이트의 편차가 작은 것도 같은 이유다. "더 극적으로" 키우고 싶은 충동을 참아야 한다.

### 함정 S3 — 봉우리를 등간격으로 놓으면 파도가 된다

정점 간격이 일정하면 구름이 아니라 **사인파**가 나온다. 간격을 110~270px 범위에서 불규칙하게 두고, `gaps` 배열 길이와 `ys` 배열 길이를 서로 다르게 하면(예: 16 vs 28) 주기가 어긋나 반복 패턴이 눈에 띄지 않는다.

### 원본 path 복제 금지

참조 사이트의 `path` 데이터 자체는 복제하지 마라 — 남의 사이트 그래픽 자산이다. 기법(viewBox 전략, 제어점 비율)만 가져오고 정점은 직접 정한다.

## 기법 A — px 고정 아치를 repeat-x로 타일링 (CSS만 써야 할 때)

SVG를 쓸 수 없는 경우의 대안이다. 반응형에는 안전하지만 봉우리가 균일해 벽지처럼 보이는 한계가 있다.

**모든 치수를 `px`로 고정하고, 화면 폭 대응은 `repeat-x` 타일 반복이 담당한다.** 화면이 넓어지면 아치가 커지는 게 아니라 **개수가 늘어난다.** 이것이 폭 무관 동작의 핵심이다.

레이어당 아치 열을 **2벌** 깔고 위상을 타일 절반만큼 어긋내면, 두 번째 열이 첫 열의 골을 메워 아치가 겹쳐 보인다.

```css
.cloud-layer {
  position: absolute;
  inset-inline: 0;
  /* 높이는 컨테이너 높이와 같게 고정하고, top으로 내린다.
     bottom을 고정하면 안 된다 — 아래 "치명적 함정 5" 참조 */
  height: 357px;
  bottom: auto;
  /* 레이어별 값 — 아래 "검증된 3레이어 설정" 표 참조 */
  --tile: 340px;   /* 타일 폭 = 아치 가로 지름 */
  --ry-a: 150px;   /* 1열 세로 반지름 */
  --ry-b: 110px;   /* 2열 세로 반지름 (작게 두어 불규칙성 확보) */
  --fill-h: 55px;  /* 아치 아래 단색 채움 높이 */
  background-image:
    radial-gradient(ellipse 50% var(--ry-a) at 50% 100%, var(--c) 0 100%, transparent 100%),
    radial-gradient(ellipse 50% var(--ry-b) at 50% 100%, var(--c) 0 100%, transparent 100%),
    linear-gradient(var(--c), var(--c));
  background-size: var(--tile) 100%, var(--tile) 100%, 100% var(--fill-h);
  background-repeat: repeat-x, repeat-x, no-repeat;
  background-position: bottom left 0, bottom left calc(var(--tile) / 2), bottom;
}
```

**핵심 포인트**

- `ellipse 50% <ry>` — 가로 반지름을 타일 폭의 `50%`로 두면 아치 지름이 타일 폭과 정확히 일치해 타일 경계에서 잘리지 않는다.
- `at 50% 100%` — 중심을 타일 **바닥 중앙**에 두면 위쪽 절반만 보여 아치가 된다.
- `var(--c) 0 100%, transparent 100%` — 색 정지점과 투명 정지점을 같은 위치에 두어 경계를 또렷하게 만든다. 간격을 주면 흐릿한 후광이 생긴다.
- 2열의 `background-position`을 `calc(var(--tile) / 2)`만큼 밀어 골을 메운다. 세로 반지름을 1열보다 작게 두면 크기가 다른 구름이 겹친 느낌이 난다.
- 마지막 `linear-gradient`가 아치 아래 빈 공간을 채운다.
- **`vw`를 쓰지 마라.** 아치 치수·`--fill-h`·레이어 `top` 오프셋 전부 `px`다. 이유는 아래 함정 참조.

### 검증된 3레이어 설정 (헤더 높이 357px 기준)

| 레이어 | 색 | `--tile` | `--ry-a` | `--ry-b` | `--fill-h` | `top` |
|---|---|---|---|---|---|---|
| 뒤 (z1) | `--color-cloud-500` | 340px | 150px | 110px | 55px | 0 |
| 중간 (z2) | `--color-cloud-300` | 280px | 135px | 100px | 55px | 62px |
| 앞 (z3) | `--color-background` | 390px | 165px | 125px | 55px | 124px |

레이어마다 타일 폭을 다르게 두는 것이 중요하다. 주기가 어긋나 반복 패턴이 눈에 띄지 않는다. 같은 폭이면 세 레이어가 한 덩어리로 움직여 벽지처럼 보인다.

375 / 768 / 1280 / 1920 / 2560px에서 잘림 없이 형태가 유지되는 것을 브라우저로 확인했다.

### 치명적 함정 1 — `circle` + `vw` 반지름은 넓은 화면에서 잘린다

`radial-gradient(circle at X% 100%, ... 26vw)`는 가로와 세로 반지름이 **같다**. 화면이 넓어지면 `26vw`가 커지는데 레이어 높이는 그대로이므로, 어느 폭부터 아치가 컨테이너를 뚫고 나가 **꼭대기가 수평으로 잘린다.**

임계 폭 = `레이어 높이 ÷ 가장 큰 반지름의 vw 비율`. 높이 357px에 최대 반지름 26vw면 `357 / 0.26 ≈ 1373px` — 흔한 데스크톱 모니터에서 바로 발생한다.

### 치명적 함정 2 — `ellipse`로 바꿔도 개수가 고정이면 여전히 깨진다

세로만 `px`로 묶고 가로를 `vw`로 두면 잘림은 막지만, **종횡비가 화면 폭에 따라 극단적으로 변한다.** 실제 측정값:

| 뷰포트 | 가로 반지름(26vw) | 세로 반지름(고정) | 결과 |
|---|---|---|---|
| 768px | 200px | 293px | 세로가 더 커서 뾰족한 산 모양 |
| 1280px | 333px | 293px | 균형 |
| 1920px | 499px | 293px | 납작 |
| 2560px | 666px | 293px | **아치 5개가 화면을 통째로 삼켜 구름 소멸, 수평 띠만 남음** |

아치 **개수가 고정**이면 화면이 커질수록 아치가 화면 대비 커진다. 타일 반복으로 개수가 늘어나야 밀도가 유지된다.

### 치명적 함정 3 — 레이어 `top` 오프셋도 `vw`면 안 된다

레이어를 `top: 6vw`, `12vw`로 계단처럼 내리면 2560px에서 오프셋이 154px·307px이 되어, 높이 357px 컨테이너 밖으로 레이어가 밀려난다. 넓은 화면에서 **앞 레이어가 통째로 사라진다.** `top`도 `px` 고정으로 두어라.

### 치명적 함정 5 — 레이어 바닥을 컨테이너 바닥에 고정하면 계단이 사라진다

아치의 중심은 **레이어 자신의 바닥**이다. 레이어를 `bottom: 0`으로 붙이고 `top`으로만 내리면 높이가 줄어들 뿐 **세 레이어의 바닥이 전부 같은 y에 모인다.** 그러면 아치 중심이 같은 높이가 되어 층이 사라지고, 세로 반지름이 가장 큰 앞 레이어가 뒤 레이어를 통째로 덮는다.

실측 예 (컨테이너 357px):

| | 레이어1 | 레이어2 | 레이어3 | 결과 |
|---|---|---|---|---|
| `bottom:0` 고정 | h357 b357 | h295 b357 | h233 b357 | 바닥 동일 → 앞이 뒤를 덮음 |
| `height` 고정 + `top` | h357 b357 | h357 b419 | h357 b481 | 바닥이 계단 → 층층이 보임 |

**레이어 높이는 컨테이너 높이와 같게 두고 `top`으로 내려라.** 아래로 넘치는 부분은 컨테이너의 `overflow: hidden`이 잘라내며, 그 잘린 영역이 곧 구름 하단의 단색 채움이 된다.

### 함정 4 — 양 끝 아치의 중심을 화면 안에 두지 마라

개별 배치 방식(기법 C)을 쓸 때만 해당한다. 중심 근처의 곡선은 거의 평평하므로, 마지막 아치 중심을 `95%`에 두면 화면 오른쪽 5% 구간에 꼭대기의 평평한 부분만 걸려 "잘린 것처럼" 읽힌다. 양 끝 아치 중심은 `-4%`, `104%`처럼 화면 밖에 둔다. 타일링 방식(기법 A)에서는 발생하지 않는다.

## 기법 C — 개별 radial-gradient 배치 (비권장)

아치마다 `at X% 100%`로 위치를 따로 지정하는 방식. 크기·위치를 자유롭게 줄 수 있어 불규칙한 구름을 만들기 쉬워 보이지만, **아치 개수가 고정이라 반응형에서 위 함정 1·2·4를 전부 밟는다.** 폭이 고정된 컨테이너에만 쓴다.

**안티에일리어싱**: 정지점이 정확히 같으면 계단 현상이 보일 수 있다. 거슬리면 `transparent` 정지점만 `calc(26vw + 0.5px)`로 미세하게 띄운다.

## 레이어 3장 쌓기

각 레이어를 절대 위치로 겹치고, 뒤쪽일수록 위로 올린다(y 오프셋을 작게).

```css
.clouds {
  position: relative;
  background: linear-gradient(to bottom, var(--sky-top), var(--sky-bottom));
}
.clouds > .cloud-layer:nth-child(1) { --c: var(--cloud-back);  z-index: 1; }
.clouds > .cloud-layer:nth-child(2) { --c: var(--cloud-mid);   z-index: 2; top: 6vw; }
.clouds > .cloud-layer:nth-child(3) { --c: var(--cloud-front); z-index: 3; top: 12vw; }
```

레이어마다 `radial-gradient`의 x 위치와 반지름을 다르게 줘야 자연스럽다. 세 레이어가 같은 배치면 단순히 색만 다른 계단으로 보인다.

## 섹션 구분용 구름 (본문 사이)

헤더와 달리 본문 사이 구름은 **아래쪽 섹션 배경색**으로 아치를 그린다. 위 섹션 위로 아래 섹션이 솟아오르는 모양이다. `--c`를 아래 섹션 배경으로 두고, 컨테이너 높이를 아치 반지름 정도로 잡은 뒤 `margin-bottom: -1px`로 이음새 틈을 막는다.

## 기법 B — SVG data URI (백업)

아치가 단순 원이 아니라 비대칭 곡선이면 A로는 한계가 있다. 그때만 SVG path를 `background-image: url("data:image/svg+xml,...")`로 넣는다. 여전히 이미지 파일이 아니므로 "CSS로 구현" 요구를 만족한다. `preserveAspectRatio="none"`을 넣어야 폭에 맞게 늘어난다.

## 접근성 · 성능

- 구름은 순수 장식이다. `aria-hidden="true"`를 붙여 스크린리더가 읽지 않게 한다.
- 그라데이션 레이어가 많으면 저사양 기기에서 페인트 비용이 오른다. 레이어당 아치는 6개 이내로 유지한다.
- 구름에 애니메이션을 넣는다면 `prefers-reduced-motion: reduce`에서 정지시킨다.
